# ADR-002: Document-Level ACL Enforcement & Early-Binding Retrieval
## Status: Accepted

## 1. Context & Enterprise Problem Statement
The `governed-contract-compliance-agent` retrieves confidential Master Services Agreements (MSAs), Statements of Work (SOWs), and rate card addenda to audit vendor invoices across multiple departments (`legal`, `procurement`, `engineering`, `executive`) and B2B enterprise tenants (`tenant_id`).

Naive Retrieval-Augmented Generation (RAG) pipelines execute global vector or keyword similarity searches first and filter out unauthorized chunks afterward in application memory ("late-binding" / post-retrieval filtering). In regulated enterprise environments (SOC 2 Type II, GDPR, HIPAA), post-retrieval filtering introduces three severe failure modes:
1. **Cross-Tenant & Cross-Department Leakage:** Unauthorized contract clauses enter application RAM, logs, or LLM context windows, creating prompt-extraction and side-channel exposure risks.
2. **Recall Degradation (`top-k` Starvation):** If a global `TOP K` query returns 20 chunks belonging to a restricted department or different tenant, post-filtering discards all 20—returning zero valid clauses to the compliance reasoning model even when authorized contracts exist.
3. **Distributed Sync Drift:** Storing document embeddings in a standalone external vector database (e.g., Pinecone/Qdrant) decoupled from relational PostgreSQL ACL metadata creates eventual-consistency windows where revoked permissions remain searchable.

## 2. Decision Drivers
- **Zero-Trust Security & RBAC/ACL Compliance:** `0%` unauthorized chunk retrieval across tenants and departments (`SOC 2` / `GDPR` compliance).
- **Exact + Semantic Recall:** Combine dense semantic search (`pgvector`) with sparse lexical search (`BM25` via PostgreSQL `tsvector`) and Cross-Encoder reranking so the agent captures both paraphrased deliverables and exact identifiers (`PO_10928`, `Section 4.2(b)`, role titles, hourly caps).
- **Single Transactional Store:** Keep relational ACL metadata, vector embeddings, lexical indexes, and LangGraph checkpoints unified in PostgreSQL 16 (`pgvector`) to eliminate distributed sync drift.
- **Defense-in-Depth Multi-Tenancy:** Enforce tenant boundaries at both the SQL query builder layer and the PostgreSQL Row-Level Security (RLS) policy layer.

## 3. Considered Options
- **Option A: Post-Retrieval Filtering in Python (`TOP K` Search -> Filter by `TenantContext`)**
  - *Pros:* Simple initial query; works with vector stores lacking native metadata predicate pushdown.
  - *Cons:* Leaks unauthorized vectors into application RAM; suffers severe recall collapse when restricted documents dominate top similarity scores; violates database-level isolation standards.
- **Option B: Separate Standalone Vector Database + Relational ACL Store**
  - *Pros:* Dedicated vector scaling beyond 50M+ chunks.
  - *Cons:* Introduces eventual-consistency windows during ACL updates or contract revocations; adds network hops and operational overhead.
- **Option C: Early-Binding Composite SQL `WHERE` Filtering + PostgreSQL Row-Level Security (RLS) in Unified PostgreSQL (`pgvector` + `tsvector`)**
  - *Pros:* Pushes composite `(tenant_id, department_acl)` predicates directly into the SQL execution plan *before* cosine distance (`pgvector`) or `ts_rank_cd` (`BM25`) scoring runs. Backed by PostgreSQL RLS (`FORCE ROW LEVEL SECURITY` + `SET LOCAL app.current_tenant_id`) as a hard database safety net. Reciprocal Rank Fusion (RRF) merges pre-filtered dense and sparse candidate sets cleanly before Cross-Encoder reranking.
  - *Cons:* Requires careful composite indexing (`tenant_id` B-tree, `department_acl` GIN, `tsvector` GIN, and `HNSW` (Hierarchical Navigable Small World) vector index and explicit transaction-scoped tenant binding.

## 4. Decision Outcome
We select **Option C: Early-Binding Composite SQL `WHERE` Filtering + PostgreSQL RLS in Unified PostgreSQL 16**.

1. **Mandatory Security Envelope (`TenantContext`):** Every call to `ContractRetrieverProtocol` and `ContractIndexerProtocol` requires an authenticated `TenantContext` (`tenant_id`, `department_acl`) derived from verified Ingress JWT claims.
2. **Pre-Retrieval Predicate Pushdown (Layer 1):** Both the dense (`pgvector` cosine distance) and sparse (`BM25` / `tsvector` rank) Common Table Expressions (CTEs) must execute with an explicit composite predicate (`WHERE tenant_id = :tenant_id AND department_acl && :department_acl::text[]`) so unauthorized rows are pruned prior to vector distance or lexical rank calculation.
3. **Database Row-Level Security (Layer 2):** The `contracts` and `contract_chunks` tables enforce `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` keyed against `current_setting('app.current_tenant_id', true)`, preventing cross-tenant reads even if a raw query omits the `WHERE` predicate.
4. **Hybrid Scoring & Reranking Pipeline:**
   - **Dense Retrieval (`pgvector`):** Cosine similarity over `text-embedding` vectors (`1536` dims) routed via LiteLLM Proxy.
   - **Sparse Retrieval (`BM25` / `tsvector`):** PostgreSQL `ts_rank_cd` over weighted `setweight` lexemes (`A` for section headers/contract IDs, `B` for clause body) to capture exact PO numbers, legal citations, and role titles.
   - **Reciprocal Rank Fusion (RRF) + Cross-Encoder Reranking:** Candidate lists are fused via RRF (`k = 60`) and scored by a Cross-Encoder reranker before returning typed `RetrievedClause` records to the orchestrator.

## 5. Consequences & Trade-Off Mitigations
- **Positive Impacts:**
  - Guarantees `0%` cross-tenant or cross-department data leakage at both query-planner and storage-policy levels.
  - Preserves `100%` of `top_k` budget for authorized contract clauses, eliminating recall starvation.
  - Keeps contract chunks, embeddings, lexical indexes, and LangGraph checkpoints ACID-consistent in one database.
- **Negative Impacts & Mitigations:**
  - *Filtered HNSW Recall Degradation on Selective ACLs:* In `pgvector >= 0.8.0` (verified `v0.8.7` in our stack), we enable `SET LOCAL hnsw.iterative_scan = 'strict_order'` inside retrieval transactions so HNSW automatically expands graph traversal until `k` ACL-matching neighbors are found.
  - *Connection Pool Tenant State Leakage:* Mitigated by wrapping every query in an explicit transaction using `SET LOCAL app.current_tenant_id = ...`, which automatically resets upon transaction commit or rollback.
  - *Future Scale Ceiling (>50M chunks):* Because retrieval is encapsulated behind `ContractRetrieverProtocol` (`src/ports/retrieval.py`), the adapter can migrate to OpenSearch or Azure AI Search without modifying domain or orchestration code.
